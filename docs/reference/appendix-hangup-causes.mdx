# Appendix E: Hangup Cause Code Table

FreeSWITCH ends every channel with a hangup cause. You see its name in the `hangup_cause` channel variable, in the `Hangup-Cause` event header, in CDRs, and in the log. To diagnose a call that failed during setup, see [Chapter 42: Call-Setup Failures](../troubleshooting/call-setup-failures.mdx#reading-a-hangup-cause).

Codes up to 127 come from ITU-T Q.850. Higher codes are FreeSWITCH additions for conditions the standard does not cover.

The SIP column is the response `mod_sofia` sends for each cause, from `hangup_cause_to_sip()` in `mod_sofia.c`. An asterisk marks causes with no explicit mapping, which use that function's default of 480 when a response is sent at all. A call that has already been answered ends with a `BYE`, not a response code. The reverse direction, from a received SIP response to a cause, uses a separate mapping, so the two do not always match.
